# Stitch to AutoCheck design system compliance

1. Read root `DESIGN.md`, the relevant installed Next.js documentation and the approved Stitch mockup. Inspect `src/app/globals.css` and existing components; treat `DESIGN.md` as authoritative when a mockup differs. Identify unspecified details rather than inventing tokens.
2. Map the five specified colors to reusable semantic Tailwind v4 theme tokens or CSS variables in `src/app/globals.css`: dominant `#FFFFFF`, secondary `#0052CC`, accent `#CF6625`, dark neutral `#001E4D`, and light neutral `#D8E8FF`. Use shared token utilities in components instead of repeated arbitrary values. Preserve existing conventions and do not assume a dark theme is specified.
3. Break the mockup into reusable React primitives in `src/components/ui/`, cross-feature compositions in `src/components/shared/`, and feature-specific elements near their route. Keep pages and layouts server-rendered by default; use `"use client"` only for interactive boundaries. Use strict types and semantic HTML.
4. For authentication, appointment and payment progress, implement interconnected circular node steppers, never solid or gradient progress bars. Completed and active nodes use accent backgrounds with white text or icons and accent preceding connectors; pending nodes use secondary backgrounds/borders with visible step numbers and light-neutral subsequent connectors. Expose the current step and labels accessibly, not by color alone.
5. Style sidebar and dropdown navigation buttons with 8px radius, 10px vertical and 16px horizontal padding, left-aligned text and inline icons. Active items have a light-neutral background, secondary text and icons, and an active left border. Hover transitions to reduced-opacity light neutral. Preserve keyboard navigation and visible focus.
6. Use 24px padding for main sections, 16px gaps between cards, form fields and buttons, and 12px rounding for main cards. Apply the specified `0 2px 8px rgba(0, 30, 77, 0.08)` shadow through a reusable token or utility. Adapt layouts responsively while retaining these standards.
7. Compare the implementation with Stitch and `DESIGN.md` at narrow and wide viewports, including active, pending, hover, focus, disabled and error states where applicable. Verify semantic labels, keyboard operation and contrast; flag any conflict between accessibility and prescribed styling for resolution. Run appropriate lint and tests.
