# Arquitectura frontend

- `src/app/` contiene rutas delgadas. `(auth)` agrupa registro, login y recuperación. `(dashboard)` agrupa `/ciudadano`, `/inspector` y `/admin`. La consulta pública `/verificar/[id]` mantiene el parámetro `hash`.
- Organiza por caso de uso en `src/features/`. Coloca esquemas, integración y pruebas junto a identidad, asistencia, certificados o disponibilidad. Comparte en `src/shared/` únicamente infraestructura estable. Usa Server Components por defecto. Los formularios, contextos y suscripciones tienen frontera Client.
- La frontera BFF de Next llama a AutoCheck REST. `/api/session/[action]` admite acciones de identidad explícitas y expone un perfil funcional reducido. `/api/asistencia` y `/api/availability/[centroId]` son adaptadores locales de alcance fijo. Las mutaciones de esta frontera requieren el `Origin` exacto del frontend. El POST local de perfil y disponibilidad permite escribir cookies al renovar. La lectura en AutoCheck sigue siendo GET.
- Login, refresh, logout y recuperación se delegan a AutoCheck, que registra o revoca la sesión Supabase. Guarda access y refresh en cookies HttpOnly, SameSite=Lax, Secure y de prefijo `__Host-` en producción. El servidor establece y borra las cookies. El cliente recibe rol, permisos, centro e ID del perfil desde `GET /api/usuarios/me`. Los contextos sirven para la presentación y las notificaciones locales.
- Valida el perfil en layouts protegidos y en las páginas que sirven el contenido. Next puede reutilizar layouts en navegación RSC. Los GET de guardas carecen de escritura de cookies. Un challenge con refresh disponible redirige a login con renovación por el BFF. Un rol desconocido, inactivo o distinto del requerido deniega. Delega propiedad, asignación, permiso y centro a AutoCheck y valida por caso de uso.
- `src/shared/api/` toma base URL y timeout del entorno del servidor, usa Bearer para las rutas protegidas y descarta redirecciones upstream. El refresh se deduplica por cliente y por refresh token en vuelo dentro de cada proceso BFF. La coordinación entre procesos o réplicas requiere infraestructura compartida y queda por validar en despliegue.
- Supabase en navegador se usa para Broadcast. Si el proyecto exige canal privado, el callback `accessToken` del SDK obtiene el access token registrado desde el BFF en memoria. El BFF conserva un solo ciclo de renovación. Cambiar de actor, cerrar sesión o cambiar centro elimina las suscripciones activas.
- Busca primero una primitiva existente que cumpla el contrato y la referencia Stitch. Aplica las pautas de diseño antes de agregar interfaz.
